## Overview

Milestone 8 (`v0.8.0`) delivers **PPAP Core** for the **Engine-Powered Quality Engineering Skills** platform: a deterministic 18-element Production Part Approval Process completeness auditor for Submission Levels 1–5, built against the **base AIAG PPAP 4th Edition (June 2006) standard only**. Per [`ROADMAP.md`](../../ROADMAP.md), OEM Customer-Specific Requirement overlays (Ford, GM, Stellantis, VW, BMW) are explicitly **v2 backlog** and out of scope for this release.

It is the platform's **third net-new domain built from scratch** (after the RCA Suite at `v0.6.0` and the NCR/COPQ engines at `v0.7.0`), and the **first milestone in which a new domain composes the engines already shipped**.

### What PPAP Core does

1. **Table 4.1 requirement lookup** — the licensed 18 × 5 element-by-level submission/retention matrix (`S` submit-and-retain, `R` retain-and-make-available-on-request, `*` retain-and-submit-on-request), encoded as individually-cited data with a verbatim legend.
2. **Element applicability** — resolves whether each of the 18 elements genuinely applies to a given part before any evidence is checked (Appearance Approval Report only for designated appearance items, Checking Aids only where an aid exists, and so on), with `APPLICABLE` / `NOT_APPLICABLE` / `INDETERMINATE` as first-class verdicts.
3. **Completeness audit** — joins package evidence × Table 4.1 × applicability into per-element verdicts (`SUBMITTED`, `RETAINED_ON_FILE`, `MISSING`, `NOT_APPLICABLE`, `INDETERMINATE`, `EVIDENCE_INVALID`) and a package readiness verdict (`SUBMISSION_READY` / `NOT_READY` / `INDETERMINATE`).
4. **Initial Process Study capability gate** — element §2.2.11, the only one of the 18 with a numeric acceptance criterion, evaluated through the existing `quality_core.spc` primitives and the `v0.3.0` stability gate.
5. **PSW field-completeness validation** — the 27 numbered Part Submission Warrant fields against the AIAG Appendix A completion rules, including the 4th-Edition prohibition on blanket statements of conformance.
6. **Cross-engine element linkage** — four of the 18 elements *are* domains this repository already ships, and evidence supplied for them is validated by its owning engine rather than merely counted as present:

   | PPAP element | Owning engine | Shipped |
   | :--- | :--- | :--- |
   | §2.2.6 Process FMEA | `quality_core.scoring` (AIAG-VDA Action Priority) | `v0.2.0` |
   | §2.2.7 Control Plan | `quality_core.controlplan` | `v0.5.0` |
   | §2.2.8 Measurement System Analysis Studies | `quality_core.msa` (Gage R&R) | `v0.4.0` |
   | §2.2.11 Initial Process Studies | `quality_core.spc` via the capability gate | `v0.3.0` |

   Linkage is **verdict-affecting**: evidence that fails its own engine's validation resolves `EVIDENCE_INVALID` and drives the package to `NOT_READY`. A "complete" PPAP package cannot contain a Control Plan that fails Control Plan validation.

### 🔒 The authority invariant

Per **Section 5, Part Submission Status**, the dispositions **Approved**, **Interim Approval**, and **Rejected** are assigned by the **customer's authorized representative** — on the Part Submission Warrant they sit under a block headed *"FOR CUSTOMER USE ONLY."*

No engine, canvas, MCP tool, or skill delivered in this milestone may emit, populate, infer, or imply any of those three statuses as its own verdict. The platform reports **submission readiness** — a supplier-side self-assessment — and nothing more. This invariant is enforced at four layers (engine, canvas, tool payload, skill body) by mandatory negative controls, and is the single most important correctness constraint in Milestone 8.

### Product Triad architecture

- **Deterministic Core** (`packages/quality-core/src/quality_core/ppap/`): typed Pydantic schemas, the Table 4.1 matrix, applicability rules, the auditor, the capability gate, the PSW validator, cross-engine linkage, `ASSUMPTIONS_LOG.md`, and a machine-checkable `CITATIONS.tsv` validated against the on-machine AIAG PPAP 4th Edition manual.
- **Visual Single-Writer Canvas** (`packages/quality-core/src/quality_core/canvas/ppap.py`): `PPAPCanvas` rendering the 18-element × Level 1–5 checklist matrix in dark/light HTML with a benchmark dataset.
- **FastMCP Tool Layer** (`packages/quality-mcp/src/quality_mcp/tools/ppap.py`): exposes `audit_ppap_package`, `lookup_ppap_requirement`, `validate_psw`, `assess_ppap_capability`, and `render_ppap_canvas`.
- **AI Agent Skill** (`skills/ppap-checker/`): `agentskills.io` compliant, enforcing Zero Inline Math / Zero Inline Adjudication — the skill never recites a Table 4.1 cell from memory, never decides an element's completeness inline, and never states or implies a customer approval.
- **Chained Client Round-Trip**: an in-process JSON-RPC integration suite validating three-way payload parity and a chained Control Plan → PPAP workflow across a single FastMCP client session.

## Release Gate Criteria

Milestone 8 (`v0.8.0`) will be considered releasable once all mandatory release gate criteria defined in [`ROADMAP.md`](../../ROADMAP.md) and [`docs/DEFINITION_OF_DONE.md`](../DEFINITION_OF_DONE.md) are satisfied:

1. **Workspace Sync & Dependency Lockdown**: `uv sync --frozen` executes cleanly across all workspace members.
2. **Headless Dependency Isolation**: `quality_core.ppap` pulls no app/UI/Streamlit-chain dependency; the `quality-mcp` export confirms zero UI-chain resolution.
3. **Static Analysis & Type Integrity**: `uv run ruff check .`, `uv run mypy`, and `uv run pip-audit` report zero errors across all packages and tests.
4. **100% Line & Branch Coverage Enforcement**: the core gate achieves 100% line and branch coverage including `--cov=quality_core.ppap`; the `quality-mcp` gate remains at 100%; the governance suites pass.
5. **Reference-Material Gate**: the AIAG PPAP 4th Edition Reference Manual is on-machine as `.md`, and all seven load-bearing sections (Table 4.1; §2.2.1–2.2.18; §3; §4; §5; §6; Appendix A) are verified present. No PPAP constant is asserted from the training deck, from model recall, or from a web search.
6. **Standards Fidelity of the PPAP Domain**: `quality_core.ppap` carries `ASSUMPTIONS_LOG.md` and `CITATIONS.tsv`; every citation traces to the on-machine manual, verified by `test_ppap_citations.py` with formatting-tolerant matching. Every Table 4.1 cell is individually traceable and the matrix contains exactly 90 entries. Any threshold or default without a published constant is explicitly labeled an engineering heuristic; the ISO 9001 / IATF 16949 non-citability limitation is recorded.
7. **🔒 Authority Gate (four layers)**: no engine result, canvas rendering, MCP tool payload or description, or skill body presents `Approved`, `Interim Approval`, or `Rejected` as a platform-produced verdict. Proven load-bearing at every layer by mutation negative controls.
8. **Submission-Level-4 Indeterminacy Gate**: a Level 4 package with no customer requirement set resolves `INDETERMINATE` end-to-end — engine, tool, and skill — and never falls back to Level 3 rules or an OEM default. Mutation-proven.
9. **Verdict-Affecting Linkage Gate**: evidence for §2.2.6 / §2.2.7 / §2.2.8 / §2.2.11 that fails its owning engine's validation resolves `EVIDENCE_INVALID` and drives the package to `NOT_READY`. Mutation-proven, with the downward-only import direction asserted by test.
10. **Capability Gate Integrity**: §2.2.11 thresholds are cited to the manual with boundary-value tests; attribute data never receives a `Ppk` verdict; the `v0.3.0` SPC stability gate fires on out-of-control data and is not bypassable.

## Retrospective & Status

**Status: Not Started — scoped.** Milestone 8 is fully scoped with 13 Epic issues (#98–#110) open under [GitHub milestone #9](https://github.com/Siddardth7/quality-engineering-skills/milestone/9). Execution follows the branch ladder `feature → test → main`, one PR per epic into `test`, in dependency order:

```
E0 → E1 → { E2 ∥ E3 ∥ E5 ∥ E6 } → E4 → { E7 ∥ E8 } → E9 → E10 → E11 → E12
```

### Scoping decisions recorded

1. **E0 is a hard P0 procurement blocker, not a conversion chore.** The on-machine PPAP artifact was audited during scoping and found to be a training deck missing Table 4.1, Section 5, the §2.2.11 acceptance criteria, Sections 3 and 6, and the Appendix A completion instructions. The lesson generalizes: **verify a reference's contents, not its filename.**
2. **Cross-engine linkage is in scope and verdict-affecting.** Four of the 18 elements map onto engines already shipped at 100% coverage; evidence that fails its owning engine does not satisfy its element. This is the platform's first genuine composition of prior milestones and the main integration risk of `v0.8.0`.
3. **Granularity is finer than prior milestones** — 13 issues, one deliverable each, versus 7 for `v0.6.0` and 6 for `v0.7.0`. No issue bundles engine + canvas + tools + skill, so each PR carries one review focus and epics E2/E3/E5/E6 can proceed in parallel.
4. **OEM Customer-Specific Requirements stay out.** Ford, GM, Stellantis, VW, and BMW overlays remain v2 backlog per [`ROADMAP.md`](../../ROADMAP.md). Submission Level 4 is therefore represented honestly as customer-defined and resolves `INDETERMINATE` rather than substituting a default.
5. **ISO 9001:2015 and IATF 16949:2016 are not citable this milestone** — both are on-machine only as scanned PDFs with no text layer. No PPAP rule may be traced to IATF §8.3.4.4.

### Readiness for Milestone 9 (`v0.9.0`)
On completion, the platform will carry eight engine-powered domains (FMEA, SPC, MSA, Control Plan, RCA Suite, NCR, COPQ, PPAP Core) and will have proven the cross-engine composition pattern. The repository will then be prepared for **Milestone 9 (`v0.9.0` — Supplier SCAR & Vendor Rating)**.
